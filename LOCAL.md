# CatProof Local · Codex and Claude Code

CatProof Local registers developer devices and observes approved installation/activity metadata. It does not control coding assistants, inspect conversations, execute their tools remotely, or count every session as a separate agent. This first release supports macOS and Linux with Python 3.11+. Windows is not supported by this collector (it uses POSIX file locks).

## What is sent

Every report contains only a schema version, increasing sequence, platform family, Codex/Claude detection flags and CLI versions, optional configured agent and MCP server names, and up to 20 recent session observations. Observations contain a per-device salted hash of the session ID, tool name, lifecycle event and client-reported time. The server records receipt time for presence; events older than 24 hours expire from reports.

No hostnames, usernames, serial numbers, IP inventory, project paths, Git remotes, prompts, code, instructions, transcripts, tool inputs/results, model responses, environment variables or provider credentials are collected. Your enrollment label and enrolling account email appear in the registry. Device identity is generated by CatProof, not inferred from hardware. Names can reveal business context: review the scan before enabling optional configuration-name reporting.

## Install and preview

1. Sign in to app.catproof.ai. Open Connector catalog → Show all connectors → CatProof Local → Set up local collector, or the Local devices tab.
2. Download the collector and inspect its source. Save it in a stable location. Python 3.11 or newer is required; no pip packages are needed.
3. In a terminal, preview detected tools without transmitting anything:

```sh
python3 catproof-local.py scan
```

The collector checks codex and claude on PATH and the standard macOS Codex application location. It runs only each detected CLI's --version command with a three-second timeout. It does not start an AI session or use a model API. Desktop-only Claude detection is not included; the adapter is for Claude Code.

Optionally preview configured names:

```sh
python3 catproof-local.py scan --include-config
```

This reads only conventional user configuration locations: ~/.codex/config.toml, filenames in ~/.codex/agents/*.toml, ~/.claude.json top-level mcpServers names, and filenames in ~/.claude/agents/*.md. Configured server keys are extracted without transmitting commands, headers or credentials. Custom config homes, project-specific configs, plugin-provided agents/tools and centrally managed settings are not enumerated in v1. Empty name lists mean none reported within this scope, not proof there are no agents.

## Enroll

A registry owner confirms their personal password and creates a labeled enrollment code in Local devices. Legacy shared-password users should first move to personal email accounts. Codes expire in ten minutes, are single use, and may be cancelled before use. Enrolling without the creator's current owner membership is rejected.

```sh
python3 catproof-local.py enroll --server https://app.catproof.ai
```

The collector displays the exact installation/name metadata, requires CONNECT, then prompts for the enrollment code without echoing it. For optional configured names, add --include-config to the enroll command. Do not put codes or credentials on the command line. A device can enroll in one registry per state directory; separate state directories support separate registries.

State lives under ~/.local/share/catproof with permissions 700. The report-only device token is stored in connection.json with permissions 600, expires after 90 days, and is shown by neither normal logs nor the dashboard. The server stores only its hash. This is a protected local file, not OS keychain storage; protect your user account and backups. Never commit that directory.

## Run

```sh
python3 catproof-local.py run --once
python3 catproof-local.py run
```

The second command stays in the foreground and sends a report about every minute. Leave it running in a terminal for a demo; Ctrl+C stops it. No background service is silently installed. For unattended use an operator can supervise this same command using launchd or systemd, with absolute paths to the collector and Python. Configure a user service, not root. Keep state outside your repository. Auto-updates and packaged installers are not included yet.

Network failures retain the last local activity observations and retry on the next interval; the collector does not spool transcripts or an unbounded event history. Authorization failures stop the collector. Reports go outbound over verified HTTPS, reject redirects, and do not use ambient proxy settings. Corporate proxy support needs separate configuration in a later release. There is no inbound listener or tunnel on the device.

## Optional lifecycle hooks

The collector reports presence without hooks. Hooks add session observations; installation detection alone never proves a client is actively running.

Preview the exact hook configuration:

```sh
python3 catproof-local.py hooks --tool codex
python3 catproof-local.py hooks --tool claude
```

To merge the four metadata hooks into user settings:

```sh
python3 catproof-local.py install-hooks --tool codex
python3 catproof-local.py install-hooks --tool claude
```

These commands back up existing JSON settings to a private timestamped file, preserve other settings/hooks, and add SessionStart, UserPromptSubmit, Stop and SessionEnd handlers. They target ~/.codex/hooks.json and ~/.claude/settings.json. Restart the client. In Codex open /hooks and review/trust the definitions before expecting events. Managed client policy may disable user hooks. Hook availability depends on the installed client version; test an ordinary new session in each client.

Hook handlers write a bounded activity file locally and return without network access. They ignore transcript_path, cwd, prompt and every other unapproved field. They never read the transcript or change decisions. The running collector picks up observations on the next report. Stop means a turn stopped, not that the process exited. SessionEnd is not guaranteed on crashes; expired observations must not be read as current process state. There is no support for subagent counting in v1.

## View, revoke and remove

Local devices shows reporting, offline, awaiting first report, expired or revoked. Reporting means a collector report arrived in the last three minutes; it does not prove a coding assistant is running, trusted or compliant. The device owner field is the enrolling account, not an independently verified OS user. Registry members can read the inventory; only owners can pair/cancel/revoke with current personal-password confirmation. Device credentials can only submit their own metadata; they cannot list agents, read devices, create accounts or alter canonical records.

To disconnect, revoke the device in CatProof, stop its collector, then run:

```sh
python3 catproof-local.py remove-hooks --tool codex
python3 catproof-local.py remove-hooks --tool claude
python3 catproof-local.py forget
```

Revoke is immediate on the server. Removing local state alone does not revoke a lost token. The dashboard retains the revoked device's last evidence; this release has no automated evidence retention policy or permanent device deletion. The pilot limit is 100 device records and 20 pending enrollment codes per registry. Reenrollment creates a new identity and token.

## Validation and trust boundary

Automated fixtures cover collector filtering, hook merge/removal, enrollment/token isolation, membership checks, replay rejection, throttling, expiry/revocation and HTTP authentication boundaries. Those tests are separate from live hook delivery in your installed clients. No existing local client settings or device enrollment are changed by publishing this feature. Local reports are self-reported evidence, not hardware attestation, endpoint security enforcement or cryptographically verified execution history.

Official client interfaces: [Codex hooks](https://learn.chatgpt.com/docs/hooks), [Claude Code hooks](https://code.claude.com/docs/en/hooks).

## Enrollment troubleshooting

The enrollment prompt hides what you paste; a blank-looking terminal line is normal. Create a new code in Local devices, use Copy enrollment code, and paste only that code into the collector prompt within ten minutes. Codes are single-use and can also become invalid if cancelled or the creator loses owner access. Do not use an account password or provider API key as an enrollment code. Never share the code in chat.

Collector 1.0.2 trims surrounding copy whitespace and recognized quote, invisible-edge and terminal paste wrappers. It rejects malformed codes before sending and distinguishes code rejection from a server access/origin rejection. A format error reports only character counts, never the entered code. Replace an older downloaded script with the current download. An old code cannot be recovered; create a new one.

Run the reporting process only after the collector prints Device enrolled. To avoid starting it after a failed enrollment, use:

```sh
python3 catproof-local.py enroll --server https://app.catproof.ai && python3 catproof-local.py run
```

An enrollment failure does not save a device credential. The later Enroll this device first message is a consequence of running the collector without a completed enrollment, not a second independent failure.

## Local Docker Compose HTTPS

Export Caddy's public CA using DEVELOPMENT.md, then enroll with:

```sh
python3 catproof-local.py enroll --server https://localhost:8443 --ca-file /tmp/catproof-local-ca.crt && python3 catproof-local.py run
```

The CA path is saved with the private device settings. Keep it available for later
reports. Certificate verification stays enabled. Non-default HTTPS ports are allowed
only for localhost, 127.0.0.1 and ::1.
